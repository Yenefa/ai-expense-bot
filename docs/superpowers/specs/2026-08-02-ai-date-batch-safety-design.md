# AI 日期与批量操作安全设计

## 背景与故障结论

当前聊天记账只把本轮文本发送给模型，模型看不到用户上一轮已经给出的日期和账目描述。模型未返回 `occurred_at` 时，客户端又直接使用当前时间，因此分轮补充金额时会把本应属于 8 月 1 日的记录写到 8 月 2 日。批量修改依赖模型自行解释“它们/刚才那批/全部”，没有批次边界、确认步骤和执行前白名单校验，因而可能把提示词中的全部近期记录移动到目标日期。

## 方案比较

1. 只增强 Prompt：改动最小，但仍把日期和批量边界交给模型，无法提供数据安全保证。
2. AI 理解 + 本地确定性安全层：模型负责提取账目和候选操作，客户端负责日期解析、上下文继承、批次绑定、白名单、预览确认和事务校验。兼顾自然语言能力与安全性，采用此方案。
3. 完全本地规则解析：最安全但会显著削弱自由表达、复杂账单理解和后续扩展，不采用。

## 目标行为

- 最近对话上下文随请求发送，使“就刚才那一堆”“金额是……”等续句能被理解。
- 中文绝对日期、相对日期由客户端确定性解析；续句只在明确表现为延续时继承最近日期。
- 新增账目缺少模型时间时，使用本地解析出的目标日期；没有日期上下文才使用当前时间。
- 日期修改只替换年月日，保留每笔记录原来的时分秒。
- 每次 AI 成功影响的全部账目 ID 作为一个持久化批次绑定到助手消息，并与账目变更在同一事务提交。“刚才那批/它们/这些”只能引用该批次。
- 删除、更新或一次新增多笔记录都先显示预览；用户确认后才在一个 Room 事务中执行。
- 模型只能操作本次实际提供的记录 ID；批次指代时进一步收窄到最近批次 ID。越界、重复、缺失、已删除或执行前发生变化时整批拒绝。
- 超时、解析失败、取消确认或 Activity 被系统回收时不执行任何待确认变更。
- OCR 识别、账单预览和 OCR 导入路径保持不变。

## 架构

### 日期上下文

新增 `ChineseDateResolver`，支持 `yyyy年M月d日`、`M月d日/号`、`yyyy-MM-dd`、`今天/昨天/前天`。它只在当前文本符合续句特征时扫描最近用户消息继承日期，避免把旧日期误套到新的独立记账。

### 对话与批次上下文

`LlmClient` 接收最近的 `user/assistant` 消息并按 OpenAI Chat Completions 顺序发送。`ChatMessageEntity` 新增可空的 `relatedExpenseIds` 字段，以逗号分隔保存一次操作产生的全部 ID；数据库从 v3 安全迁移到 v4。旧的 `relatedExpenseId` 保留，保证兼容旧数据和旧备份。

### 计划、确认与提交

新增 `ChatLlmCoordinator`：

1. 读取最近聊天、活跃账目和最近批次。
2. 调用模型并解析候选结果。
3. 用本地日期规则归一化时间，用白名单和批次规则校验动作。
4. 单笔新增可立即提交；多笔新增、任何更新和删除生成短期确认令牌及中文预览。
5. 确认时重新校验目标记录快照，并通过 `LlmMutationApplier` 在同一事务提交。

待确认计划只保存在进程内。进程终止会丢弃计划而不是误执行，这是故意的安全策略。

### UI

聊天页显示 Material 3 确认对话框，列出操作类型、笔数、合计、原日期和目标日期。按钮为“确认执行”和“取消”。发送期间以及确认期间避免重复提交。

## 错误处理

- 没有可解析批次时：“无法确定‘刚才那批’具体指哪些账目，本次未修改。”
- 模型返回提示词外 ID 时：“AI 返回了不在本次范围内的账目，本次未修改。”
- 确认前账目已被手动编辑时：“账目已发生变化，请重新发起操作。”
- 请求超时和服务错误只写安全错误消息，不产生数据库变更。

## 测试与验收

- 单元测试覆盖中文日期、跨年规则、续句继承与非续句不继承。
- 单元测试覆盖上下文消息顺序与当前消息不重复。
- 单元测试覆盖批次白名单、越界拒绝、日期替换保留时间、多笔确认和事务回滚。
- ViewModel 测试覆盖确认、取消和批次 ID 持久化。
- Room 迁移测试覆盖 v3 到 v4 数据无损。
- 最终运行 `testDebugUnitTest`、`compileDebugAndroidTestKotlin`、`lintRelease`、`assembleRelease` 以及项目现有契约脚本；验证 APK 签名证书与上一版一致。

## 非目标

- 不更换或削减 OCR 模型与 OCR 导入能力。
- 不尝试用本地规则取代所有自然语言理解。
- 不自动恢复截图所示已经被移动的数据；缺少实体设备数据库时无法可靠确定原始 20 个 ID。
