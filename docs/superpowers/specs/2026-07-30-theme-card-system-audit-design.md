# v3.6 深浅色卡片系统统一设计

## 目标

统一应用内所有卡片型组件的深浅色表现，修复以下问题：

- 智核分析底部摘要卡片硬编码为白色，深色模式下与页面不匹配。
- 部分强按钮或选中项在深色模式下出现浅色背景配白色文字，导致内容接近不可见。
- 多个带阴影的卡片仍使用页面背景色，深色模式下缺少层级。
- 液态思考按钮的黑白装饰色没有跟随主题。

本次保持现有布局、圆角、尺寸、动效与业务逻辑不变，只统一容器和前景配色。

## 统一语义色

在 `AppColorPalette` 中新增 `CardBg`：

| 语义 | 浅色模式 | 深色模式 |
|---|---|---|
| 页面背景 `Bg` | `#FFFFFF` | `#1C1C1E` |
| 卡片背景 `CardBg` | `#FFFFFF` | `#2C2C2E` |
| 次级填充 `ChipFill` | `#F4F4F4` | `#2C2C2E` |
| 主文字 `TextPrimary` | `#0D0D0D` | `#F2F2F2` |

配色规则：

1. 页面根背景继续使用 `Bg`。
2. 带圆角、阴影或悬浮层级的卡片和弹层使用 `CardBg`。
3. 输入框、消息气泡、未选中的次级控件使用 `ChipFill`。
4. 使用 `TextPrimary` 作为强按钮或选中项背景时，前景使用 `Bg`，形成浅色黑底白字、深色浅底深字的对应关系。
5. Material `surface` 对应 `CardBg`，让默认对话框等组件自动跟随卡片系统。

## 硬编码颜色处理

需要替换：

- 卡片容器中的 `Color.White`
- 以 `AppColors.TextPrimary` 为背景时错误使用的 `Color.White` 前景
- 液态按钮中用于主体、边框和高光的固定黑白色

保留：

- 蓝色发送按钮上的白色图标
- 红色删除按钮上的白色图标和文字
- 黑色半透明弹窗遮罩
- 恢复、删除、错误状态的语义色
- 分类图表的固定分类颜色

这些保留项表达明确的操作或数据语义，不属于卡片主题错误。

## 验证

采用三轮检查：

1. **硬编码扫描**：扫描 `Color.White`、`Color.Black`、固定十六进制颜色，逐项确认是否属于保留范围。
2. **组件扫描**：扫描 `Card`、`Surface`、`softShadow`、圆角 `background`、弹层和按钮颜色，确认容器使用正确语义色。
3. **构建验证**：为 `CardBg` 与前景对比增加单元测试，运行全部测试和真实 128 条 CSV 导入样本，再构建并校验 v3.6 APK。

由于当前没有连接 Android 设备，代码、测试与 APK 可以完整验证；最终视觉效果仍需要安装到手机后确认。
