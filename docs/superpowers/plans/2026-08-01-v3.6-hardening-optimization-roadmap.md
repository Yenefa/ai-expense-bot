# Y.E cost v3.6 Hardening and Optimization Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each approved phase task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden privacy and data integrity, improve lifecycle behavior, reduce delivery risk and APK size, and remove unfinished UI without destabilizing the Android 8-13 compatible v3.6 release.

**Architecture:** Treat every improvement as an independent, testable phase. Preserve the current Room schema, application ID, installed-user upgrade path, and signing certificate unless a phase explicitly requires a reviewed migration. Execute only one phase at a time against the existing dirty working tree and never reset, checkout, or overwrite unrelated edits.

**Tech Stack:** Android API 26-34, Kotlin 1.9.22, Jetpack Compose, Room 2.6.1, DataStore, OkHttp, ML Kit OCR, Gradle 8 / AGP 8.2.2, PowerShell release tooling

---

## Global delivery contract

- Preserve all pre-existing modified and untracked files.
- Add a regression test before each behavior change and verify that it fails for the intended reason.
- Run the focused test after each edit, then run unit tests, Lint, and the Release build before delivery.
- Sign every delivered APK with certificate SHA-256 `e5ac68a1544da24122eee453eebc758286644940167fce1a72e983455b3c2b5c`.
- Copy final APKs only to `C:\Users\fuker\Desktop\app\codex change` and publish their SHA-256 hashes.
- Treat Android 8-13 physical-device validation as a separate required gate when a change affects startup, navigation, rendering, shrinking, or packaged native code.

## Deferred work

Bulk dependency upgrades, wholesale navigation replacement, and SQL-based analytics aggregation are outside this roadmap until profiling, compatibility evidence, or a concrete feature requirement demonstrates a benefit.
